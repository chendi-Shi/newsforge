# NewsForge v2：可复核的时间回放、召回消融与 CPU 服务结果

内部冻结候选为 `popular_only`，服务重排为 `关闭`；5,000 个 dev 请求的全点击 Recall@100 为 **44.4694%**，Recall@10 为 **23.4820%**。内部选出的独立曝光排序模型 `full-seed29` 在全部 376,471 个 dev 曝光组上，nDCG@10 为 **0.420052**。候选召回、曝光内排序和 HTTP 性能是三种不同测量。

本轮是在看过 v1 dev 结果之后开展的后续研究。窗口、候选和模型仅用内部验证选择，随后冻结配置并完整报告预定 dev 消融；这不能恢复 dev 为从未使用的独立测试集。滚动方法还使用已成熟的过去验证/dev 反馈，因此与 v1 冻结反馈的数值差不能直接归因为相同信息下的算法改进。

## 时间与实验口径

请求时刻 t 对应整点 T=floor(t/3600)×3600，统计及目录截止 C=T−3600；只允许 source_timestamp<C 的事件，first_seen<C 的文章。时间无源时区，UTC 只是确定性排序坐标。首次观察年龄不是发布时间，至少 1 小时并按整点成熟的反馈是回放假设。EMA 半衰期 12 小时，事件按小时结束聚合。

三种排序输入为内容 15 维、时间上下文 7 维及合并 22 维；共享 100,000 个训练正例，各配 4 个同曝光负例，共 500,000 行。固定 HGB 80 轮、15 叶、63 bins、学习率 0.1、L2=1，关闭提前停止，单 CPU 线程。seed 为 17/29/43；这是分箱等随机性的重复，不能称为神经网络初始化。1:4 采样输出只用于排序，不能解释为总体校准 CTR。

## 消融调度缓存：等价验证与实际计时

从内部验证固定抽取 16 个请求（seed=2026），对 9 个候选方案按 ABBA 顺序执行，共逐字段比较 **576 个 CandidateBatch**。不一致 0 个，最大分数绝对误差 0.000000；ID、分数、dtype、来源、mask、时间截止、shortfall 和 metadata 均精确一致。这项审计没有做 dev 相关性评估，也不参与选模型。

每次观测前清除目录与请求路由缓存，另有一次不计时的相同请求预热；表中计时包含整轮检索、精确等价检查和调用计数 instrumentation。这里只复用同一请求、同一语义路由的 top IDs，热度反馈、融合与过滤仍按方案执行。它改变实验调度，不改变推荐结果；少量共享桌面的观测不是稳定性能保证。HTTP 服务默认关闭该请求路由复用，不能把此处的调用减少或任何整轮计时解释为服务延迟提升。

观测服务进程峰值 RSS **183.45 MiB**；系统最低可用内存 762.42 MiB。每 0.1 秒采样，共 376 次，覆盖服务健康后的 API 校验和压测，排除启动阶段和客户端；采样可能遗漏瞬时峰值。

API 契约通过 **13/13**；整体报告 passed=`true`。检查包括 PAD/OOV、时间覆盖外拒绝、覆盖端点、整点前后 cutoff、非法 top_k/批大小及空历史。逐请求对比推荐 ID、来源、分数与配置/快照/模型版本。
