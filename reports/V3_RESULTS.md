# v3 实测：有界个性化与等价检索优化

本轮在冻结热度候选上获得小幅前十覆盖增益，并测得热缓存检索加速。独立时间确认通过预设门槛；但新增显式列组和历史门控没有分别证明正增量。全部结果来自真实 CPU 执行，计算协议在正式运行前冻结，见 [V3_PROTOCOL](../docs/V3_PROTOCOL.md)。v1/v2 源码及证据未改写。

## 数据和训练

数据继承 MIND-large：2,609,219 曝光组、97,592,931 候选曝光记录。内部 fit/tune/confirm 分别使用 2019-11-14 的 `[09:00,13:00)`、`[14:00,18:00)`、`[19:00,23:00)`，各 20,000 / 2,000 / 2,000 请求；中间空出反馈成熟缓冲。时间为源数据的确定性 epoch 坐标。

每 seed 使用相同 fit 行，每正例从同曝光非点击项中放回抽 4 次，排除与该曝光正例 ID 冲突的项，最终均为 **126,660 对**。同 seed 三变体共享配对，配对等权，多点击曝光和重复抽样带来更多权重。非点击不证明用户不感兴趣，本轮没有把未曝光目录新闻伪造为负例。

模型是无截距成对 logistic，固定 L2=0.01、L-BFGS-B 最多 200 次迭代；仅 fit 配对估计总体均值和标准差。所有 9 次优化均成功收敛，完整迭代数、梯度、参数与样本摘要见 [fit.json](v3/fit.json)。seed 随机性来自负例抽样，不是神经网络初始化。

| seed | full13 目标值 | 去显式类别列 | 去最后历史专用列 |
| --- | ---: | ---: | ---: |
| 17 | 0.665488 | 0.665557 | 0.665489 |
| 29 | 0.666819 | 0.666866 | 0.666820 |
| 43 | 0.664734 | 0.664796 | 0.664743 |

三个模型各自先截断至 [−1,1]，再等权平均，乘历史长度门控 n/(n+5) 和 δ，加入负原始排名。候选固定最多 100 条；相距至少 2δ 的原排名不能逆转，但这不是每个物品最多移动 δ 位的保证。

## 选择、确认与冻结 dev

调参只选择预定 `full13 + gate` 的 δ；2,000 请求、3,027 点击分母，δ=0/2/5/10 的 Top10 命中分别为 **303/303/302/305**，因此选 δ=10。并列取较小 δ。[全部调参记录](v3/tune.json)

确认段有 3,021 个点击，基线命中 430，新方案命中 441：R@10 **14.2337% → 14.5978%**，增益 **+0.3641 pp，用户簇 95% CI [0.0668, 0.6396] pp**。点值和区间下界均为正，通过预设部署门槛。参数和模型不再改变；新服务最早允许源时间 2019-11-15 00:00 的请求。[确认记录](v3/confirm.json)

dev 沿用 v2 的 5,000 请求、7,576 全部日志点击分母，7,533 个点击目录可用且非已读；所有请求都得到 100 个候选。区间为 1,000 次、seed2026 的配对用户簇 bootstrap，计算总命中差/总点击数，不是逐请求 Recall 均值。

| 冻结方案 | Top10 命中 | Recall@10 | 相对热度 Δ / 95% CI（pp） |
| --- | ---: | ---: | --- |
| 热度基线 | 1,779 | 23.4820% | — |
| **full13 + gate（实际服务）** | **1,811** | **23.9044%** | **+0.4224 [0.1066, 0.7618]** |

## 各部分是否带来收益

| 对照（完整方案减去消融） | R@10 差 / 95% CI（pp） | 结论 |
| --- | --- | --- |
| 显式类别重叠列 | −0.0132 [−0.0399, 0.0000] | 没有正增量证据 |
| 最后历史专用交互列 | 0.0000 [0.0000, 0.0000] | 本样本 Top10 点击命中相同，不代表全部分数和顺序相同 |
| 历史长度门控 | −0.0660 [−0.2499, 0.0936] | 区间跨零，没有稳定正收益证据 |

这是列组消融：完整特征余弦仍含类别信息，其他历史聚合也仍含最后一次行为。删除两类专用列不等于完全擦除其信息。`no_gate` 保留空历史回退，其 dev 点值较高，但没有经过预定主方案的确认流程，因此不根据此表改选服务。多个 dev 消融区间未经多重比较校正，属于探索性结果。

## 检索优化与真实服务

优化保持 v2 输入、排序、完整已读过滤、回填和元数据定义，缓存每小时排序与成员关系，只检查足够长的候选前缀，并移除热门路径中无用的双塔编码。每个请求仍从严格滞后反馈构建候选。

同 64 条成熟内部请求，每模式三轮 ABBA；共 **1,536 个 CandidateBatch，每批 9 个字段完全一致，容差为零**。下表的时间仅计 `retrieve` 调用；每种实现/模式有 384 次测量。

| 状态 | v2 总时间 | v3 总时间 | v2/v3 时间比 | v2 / v3 p95 |
| --- | ---: | ---: | ---: | --- |
| 冷派生缓存 | 19.8893 s | 20.3560 s | **0.9771×** | 64.158 / 74.362 ms |
| 热小时缓存 | 1.2978 s | 0.5004 s | **2.5935×** | 5.808 / 2.103 ms |

冷指清除派生缓存，不是冷 OS 页缓存。热模式显式预热不计入上表。三轮热缓存比值为 2.634 / 2.277 / 2.953，冷缓存为 0.855 / 1.002 / 1.093；这些是本机观测比值，不是速度提升的统计置信区间。热缓存最大数组占用从 13,389,888 降至 7,528,160 字节；该微基准同进程同时加载两种输入，进程 RSS 不能归因于单个实现。[ABBA 原始聚合](v3/fast_retrieval_benchmark.json)

HTTP 使用另一个固定 64 条 dev 请求集，每配置完整运行三轮，预热另计。离线参考进程退出后才启动实际服务；本机单 worker、单计算线程，localhost 每请求新连接，时延包括序列化、连接、排队、检索、残差计算和解码。

| batch / 并发 | 测量查询数 | 查询吞吐 / s | 整个 HTTP 请求 p95 |
| --- | ---: | ---: | ---: |
| 1 / 1 | 192 | 31.63 | 63.20 ms |
| 8 / 1 | 192 | 36.66 | 344.50 ms |
| 1 / 4 | 192 | 32.32 | 197.27 ms |
| 8 / 4 | 192 | 33.84 | 1,053.14 ms |

全部 **768 次查询零 HTTP 错误、零离线响应不一致**，13 项契约检查通过；逐字段比较包括分数，使用严格相等。健康服务窗口峰值 RSS **237,432,832 字节（226.43 MiB）**，不含启动期和客户端。本机共享负载未经控制，不能将与旧版不同样本/不同时间的 HTTP 数字直接解释为加速，也不能宣称生产容量。[服务报告](v3/service_benchmark.json)

## 审计与局限

[193 项测试](v3_release_unit_tests.txt)通过；[独立审计](v3/release_integrity.json)核验 **134 个文件摘要**，从原始曝光核对全部配对，重算 fit 标准化与目标、canonical 热度候选、分母、排序、四个 δ 的选择、用户簇区间及部署门槛。v3 热度基线逐请求命中与冻结 v2 一致。

另外固定抽取 64 个质量评估请求，独立从缓存分数得到的 Top10 ID/顺序与实际加载的 V3Engine 全部一致。630 个有效重排分数最大绝对差 **7.59×10⁻⁷**，低于预先声明的 10⁻⁵ 容差；差异来自带 PAD 的离线历史与去 PAD 服务历史的 float32 归约。另一个空历史请求严格回退。此对照将质量缓存与真实服务相连；上述 HTTP 对照则验证传输链路所有字段完全一致。

官方 dev 已被此前版本观察，本轮不是未见测试集。继承热度窗口曾使用旧内部数据选定，新的时间分隔不能消除这种研究历史。区间条件于同一天已实现的反馈流，不覆盖跨日期漂移和全部开发选择；原始日志点击不是完整相关性标签，也不是线上 CTR 或因果收益。审计独立重算分数和排序，但内容特征提取采用源码与缓存摘要绑定，没有另写一套数学实现。
