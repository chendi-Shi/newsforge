
本机执行涉及两个从 GitHub 创建的克隆，均固定提交 `d1b7ef285614a50ee86bcf62c2147a388e355d13` 并使用上述同一隔离环境。第一份克隆位于深层工作目录，完成本报告的 v3 重训练和新模型 HTTP。第二份位于用户目录下的短路径，[重新导入同一冻结制品包](delivery/short_clone_import.json)后完成联合验收。两份克隆的用途分别记录，所有结果并非来自同一克隆的一次连续运行。

## 新训练模型到 HTTP：通过

[新模型 HTTP 报告](delivery/retrained_http.json) 已通过，服务加载本次重新训练产生的选择、拟合和确认结果。固定 64 个 dev 请求经过四种 batch/concurrency 配置、每组三轮，共 **768 个正式查询**；所有响应字段及数值分数与独立离线参考严格相等，HTTP 错误、失败查询、响应不匹配均为 **0**。**13 项 API 契约全部通过**；离线输出额外核查了 640 个返回项的唯一性、已读过滤及时间有效性。

| batch | concurrency | 正式查询数 | 吞吐量（query/s） | HTTP 请求 p95（ms） |
|---|---|---|---|---|
| 1 | 1 | 192 | 25.99 | 87.58 |
| 8 | 1 | 192 | 39.65 | 325.96 |
| 1 | 4 | 192 | 52.58 | 129.94 |
| 8 | 4 | 192 | 85.68 | 408.33 |

延迟按整个 HTTP 请求计算，因此 batch=8 的延迟包含八个查询；吞吐量按查询计算。单个受控服务进程的健康运行阶段峰值 RSS 为 **237,178,880 字节（226.19 MiB）**，不含客户端和服务启动阶段；199 次资源采样没有错误。测量在共享桌面 CPU 上完成，报告本次观测，不与历史不同运行条件拼接为性能加速比。

## 冻结发布制品联合验收：通过，保留首次失败

深层克隆的首次联合验收通过源代码、隔离环境及 `pip check` 后，在单元测试阶段失败：发现 **251 项测试，13 个错误，1 项跳过，测试用时 46.737 秒**。制品测试的失败临时路径长度均为 **263 个字符**，超过 Windows 常见的 260 字符限制。这次运行未进入联合验收的 HTTP 阶段，未计为通过。[失败验收凭据](delivery/attempts/deep_path_acceptance.json)与[脱敏测试摘要](delivery/attempts/deep_path_tests.json)保留，已完成的重训练及独立新模型 HTTP 证据不因此改写。

后续在短路径 GitHub 克隆中固定相同提交、使用同一个隔离解释器并重新导入冻结制品，完整联合验收已通过。[acceptance.json](delivery/acceptance.json) 的 `status=passed`、`passed=true`，总耗时 **197.170 秒**；同一次运行完成了 Git 来源与前后源文件校验、隔离环境检查、依赖检查、单元测试和真实 HTTP 验证，没有使用 `--skip-tests`。

[本机测试日志](delivery/unit_tests.txt)记录 **251 项发现、249 项实际执行通过、2 项跳过、0 个错误**，测试内部耗时 56.531 秒。两项跳过均因本机账户不能创建符号链接；它们在独立 GitHub runner 中执行通过。本机跳过数没有计入通过数，也没有被隐藏。
