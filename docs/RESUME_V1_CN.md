# 简历写法与证据边界

项目名称：**NewsForge：基于真实曝光日志的两阶段新闻推荐研究与推理服务**

- 构建 MIND-large 新闻推荐实验管线，流式处理 260.9 万曝光组、9759.3 万候选记录；实现时间切分、仅训练集拟合文本特征及全候选评估。
- 实现双塔召回、候选相关注意力重排及 GBDT 对照，在 376,471 组完整 dev 上完成神经模型三种子评估；随机负例双塔 nDCG@10 为 0.3858 ± 0.0071，固定内容相似度基线为 0.3716。
- 开发 FAISS HNSW + FastAPI 服务，支持批量推理、时效与已读过滤及冷启动回退；本机 CPU 单请求串行 p95 30.57 ms、69.72 查询/秒，ANN 邻居 Recall@100 为 0.8913。
- 可选：优化 CPU 离线评估分批，在固定 12,000 个内部曝光上，将 GBDT 候选计算槽从 2,217,760 减至 486,720，四项逐组指标在 1e-12 容差内等价；此次原序/分桶耗时为 82.00/40.05 秒。该结果为共享桌面单次配对，不代表通用或生产加速。

以上四条可选，投递时优先保留前三条；岗位更重视 CPU 性能时可用第四条替换。面试时展示 `reports/RESULTS.md`、原始 JSON 和复现命令。

统计口径：双塔数值是预先指定的随机负例方案在三个种子上的均值 ± 样本标准差，不是选取 dev 最佳种子；各神经模型的 epoch 均按内部验证选择，dev 不参与选择。内容相似度为固定基线，GBDT 使用不同训练预算。随机/混合负例及注意力模型的完整对照、按用户聚类 bootstrap 区间见实测报告。

服务性能口径：单请求串行数据来自 384 次本地 HTTP 请求，ANN 校验使用 125 个内部验证查询；共享 Windows 桌面的 CPU 负载未受控，延迟与吞吐只代表本次环境，不是生产 SLO。

项目身份是个人开源研究项目，以上表述只能在你能解释并演示代码与实验后使用。不能写成腾讯生产业务、真实线上 CTR 提升、在线 A/B、分布式集群加速、预训练语言模型微调或完整 NRMS 复现；本次实现和实测未覆盖这些内容。

混合负例训练方案的实验结论：混合负例训练方案（按验证选择 epoch）在本设置下的 nDCG@10 低于同样按验证选择 epoch 的随机负例方案；不能把它写成有效优化。后续可在新的内部实验中研究假负例、样本难度与训练稳定性。 混合方案有 2/3 个种子选中仅用随机负例训练的第 1 轮 warm-up；随机方案有 0/3 个种子选中第 1 轮。最终测试比较的是按内部验证选择 epoch 的训练方案；对于选中 warm-up 的混合方案，最终权重未包含第 2 轮难负例更新，不能把测试差值归因于未被选中的难负例权重。

岗位对应：用户行为建模与本报告规模的日志处理；PyTorch 模型/优化与实验设计；CPU 检索和批量推理；本机推荐服务实现。分布式训练与在线实验属于后续扩展，当前不列为完成经历。
