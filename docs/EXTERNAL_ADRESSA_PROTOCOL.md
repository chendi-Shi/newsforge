# Adressa 外部冻结模型迁移协议 v1

状态：**预注册方案，尚未下载或读取 Adressa 事件、尚无实验结果**。本文件及 `reports/external/adressa_source.json` 应在下载前提交并记录 Git commit；执行实现及合成测试也必须在读取目标数据前冻结。代码修复应保留失败目录和原因，不能根据收益修改方案。

## 研究问题与解释边界

验证已经在 MIND 上冻结的 v3 有界残差模型，在另一个出版商、语言和时期的阅读日志中，是否还能改善固定热度候选前十项的下一阅读事件覆盖，以及时序与候选集合不变量是否成立。数据为 NTNU / Adressavisen 官方 **Adressa light 一周包**，原始记录期为 2017 年 1 月 1–7 日。官方字段和许可见[数据主页](https://reclab.idi.ntnu.no/dataset/)、[字段说明](https://reclab.idi.ntnu.no/dataset/cxdataset_v5.pdf)、[CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/)。只发布代码和汇总，不发布记录、标题、匿名用户标识或模型输入数组。

这是独立数据集上的**跨语言、跨出版商、回顾性冻结模型压力测试**。MIND 模型训练于 2019 年数据，Adressa 来自 2017 年，不能称为未来时间泛化。Adressa light 只有已发生的页面访问事件，没有完整曝光列表和未点击项；目标称为“下一阅读事件”，不能假装具有曝光负例、CTR、曝光 AUC、反事实策略价值或线上 A/B 收益。它不会替代原 MIND 任务的效果证据，也不证明线上部署有效。

英文 TF-IDF 词表对挪威语缺少覆盖，类别也通常不匹配。这种迁移不适合作为跨语言语义模型能力的证明，但可以如实检验现有冻结模型的退化和排序稳健性。不翻译、不换编码器、不拟合新类别词表、不调整权重；负收益或无收益也是正式结果。不得据本实验替换原部署方案。

## 1. 输入、来源与身份

- 唯一外部数据源：`https://reclab.idi.ntnu.no/dataset/one_week.tar.gz`。研究阶段仅做 HEAD，返回 200、Content-Length 为 1,414,905,649 字节；实际下载必须重新核验响应，流式计算 SHA256，再写入新的 acquisition receipt。本协议不预先捏造原始包摘要。
- 原始文件保存到忽略目录 `data/external/adressa/raw/one_week.tar.gz`；处理数据、逐请求预测、日志保存到 `artifacts/external/adressa_v1/`，汇总保存到 `reports/external/adressa_v1/`。不覆盖旧 MIND 数组、模型或报告。
- tar 只允许普通文件和目录，拒绝绝对路径、`..`、盘符、链接及重复成员名；禁止不受约束的 `extractall`。优先在归档流中逐行读取，不展开 JSON 为巨大 Python 对象列表。
- 记录原始成员名称、字节大小与 SHA256，但公开报告只含非个人化文件名及聚合计数。事件物理身份固定为 `(member_name, one_based_line_number)`；先按成员名 UTF-8 字节序再按行号确定稳定输入顺序。
- 必须有非空字符串 `userId`、整数 Unix 秒 `time`、非空字符串文章标识。文章 ID 使用 `id`，缺失时使用 `documentId`；若二者同时存在且不同，中止并保留 schema failure，不凭结果选择一种。标题和类别分别使用 `title` / `category`；缺失或非字符串视为空串，单列计数。其余字段不进入特征。
- JSON 错误和必要字段错误按原因计数。整个数据中只保留上述结构合法、落在预定时间范围内的访问记录；不按标题词数、用户历史长度、模型可用性、目标是否在目录或任何命中结果过滤。记录总数、合法数、范围外数、缺字段数，不能隐藏数据损失。
- 页面访问可能重复或刷新。对完全相同的 `(userId, time, article_id)` 仅保留物理身份最小的一条，记录去重数。这是预定事件定义，不声称辨识了所有真实重复点击。不同文章的同秒事件均保留，且互相不可见。

## 2. 固定日期、样本与预算

时间使用原始 Unix 秒的 UTC 坐标，不重写为 MIND 日期：

| 部分 | 半开区间（UTC） | 用途 |
|---|---|---|
| 暖机 | `[2017-01-01 00:00:00, 2017-01-05 00:00:00)` | 建立过去可观察文章、用户历史和延迟热度状态；不拟合模型 |
| 评估日 1 | `[2017-01-05 00:00:00, 2017-01-06 00:00:00)` | 最多 5,000 个请求 |
| 评估日 2 | `[2017-01-06 00:00:00, 2017-01-07 00:00:00)` | 最多 5,000 个请求 |
| 评估日 3 | `[2017-01-07 00:00:00, 2017-01-08 00:00:00)` | 最多 5,000 个请求 |

每个合法去重后的访问事件形成一个查询：在其时间 `t` 前预测该事件访问的文章。每天以 `SHA256(UTF8("newsforge-adressa-v1|" + YYYY-MM-DD + "|" + member_name + "|" + decimal_line_number))` 升序取前 5,000 行，hash 相同按物理身份排序。一天不足 5,000 则全部使用并报告不足，不换日期。样本选择不使用目标文章、标题、历史长短、模型得分或命中。正式评分前保存样本身份摘要；公开报告不暴露用户 ID。

所有合法事件（包含未抽中的事件）只在满足下述时间边界后更新公共状态。总评估最多 15,000 请求。安全计算上限为 10,000,000 原始行、200,000 文章、2,000,000 用户、25 GiB 解压后字节；越界失败并报告，不静默截断成有利样本。单进程、数值线程 1、文本 transform 批量最多 4,096、候选至多 100、历史特征至多 20、bootstrap 1,000 次。预计下载 1.42 GB，处理与评分通常应在几十分钟量级；这是工程估算，不是已测时长。正式运行记录实际耗时、RSS 峰值、包大小和输入计数。

## 3. 因果状态与候选目录

先按 `(time, member_name, line_number)` 稳定排序。请求历史仅使用**同一用户 `event_time < t` 的过去事件**；同秒事件整组预测完成后才加入用户历史。画像取最近 20 条访问事件（保留不同时间的重复阅读）；过滤候选时排除该用户所有 `event_time < t` 的已读文章。空历史请求保留。

文章 `first_seen` 为整个事件流中第一次合法访问时间。文章标题和类别固定取最早事件的版本，同秒按物理身份选择；不使用后续更完整标题修补早期记录。首次标题为空则一直为空，并报告比例。它是首次观察代理，不是真实发布时间或已恢复的历史页面快照；`publishTime` 不用于提前引入尚未观察的文章。该规则防止利用未来新文章或后续标题修订，但仍受原日志抓取语义限制。

对于请求 `t`，`T=floor(t/3600)*3600`，`C=T-3600`。公共热度只使用 `event_time<C`，`event_time=C` 必须排除。沿用原 v2 每小时衰减、半衰期 12 小时的递推：

```text
state(C) = 2**(-1/12) * state(C-3600) + histogram_of_read_events[C-3600,C)
```

每个去重访问事件最多更新一次，不能因五个方法、消融或重复评估而重复累计。这里的 `state` 是访问量，不假称曝光量或 MIND 点击率。本外部适配器不制造 exposure 数组。

可见目录只含 `first_seen<C` 的文章，并排除全部已读历史。近期目录还满足 `first_seen>=T-24*3600`。按 `(EMA_read_count 降序, first_seen 降序, article_id UTF-8 字节序升序)` 排序，从近期目录取最多 200，再取前 100；不足 100 时按同一规则从整个可见目录补未读项。全目录也不足时保留真实 shortfall，不加入当前目标或未来文章。

该适配保留原方案的 100/200 预算、24 小时首次观察窗、全历史过滤、12 小时 EMA 和 1 小时严格截止。由于源数据没有曝光，原 v2 的曝光量次级并列键不适用，本测试明确只迁移上述访问热度基线和冻结 v3 内容排序层；不声称直接运行未修改的 MIND 服务数据契约。不得伪造编码器训练日期或平移时间来绕过原服务的 2019 年成熟检查。

## 4. 真实复用冻结 MIND 模型

输入路径均相对仓库；在正式执行前记录以下文件 SHA256，并与预注册来源报告中的值一致。数据包、模型和 joblib 只使用本仓库已验证产物，不加载网络来源可执行序列化对象。

- `data/processed/tfidf.joblib`、`data/processed/svd.joblib`、`data/processed/category_vocabulary.json`、`data/processed/manifest.json`。
- `artifacts/v3/selection.json`、`artifacts/v2/selection.json`、`reports/v3/fit.json`、`reports/v3/tune.json`、`reports/v3/confirm.json`。
- `artifacts/v3/models/{full13,no_category,no_recent}-seed{17,29,43}.npz` 及各自 `.npz.json`；全部 9 份权重、mean、scale 保持原样。
- `newsforge/data.py`、`newsforge/v2/ranker.py`、`newsforge/v2/temporal.py`、`newsforge/v2/retrieval.py`、`newsforge/v3/residual.py`、`newsforge/v3/fast_retrieval.py` 及原 `docs/V3_PROTOCOL.md`。

每篇外部文章只使用冻结的首次标题字符串作为 text，摘要为空（不拼接 keywords、正文或翻译）。调用原 TF-IDF 的 `.transform`，再调用原 SVD `.transform`，按原规则 L2 normalize 为 float32，填入原 96 文本维；不调用任何 `.fit` 或 `.fit_transform`。类别不翻译、不做语义映射，按冻结 MIND category vocabulary 精确匹配；未知类别置原 UNKNOWN one-hot 列。padding 行全部为零。保持原输入总维数，未知类别不是空白历史。

必须公布词表覆盖诊断：全目录标题为空比例、TF-IDF 零非零元行比例、SVD 零范数比例、未知类别比例，以及评估候选/历史的相同诊断。不因覆盖差而删除请求、回退到另一个编码器或改用重新训练模型。

使用原 `newsforge.v2.ranker.content_features` 计算 15 维特征并取前 13 列，调用原 `PairwiseResidual.load` / `predict_raw`。正式方法固定为：热度 baseline、`full13+gate`（唯一主比较）、`no_category+gate`、`no_recent+gate`、`full13+no_gate`。所有方法共享每请求原始 100 候选和同一历史；消融使用原已训练对应三 seed 权重。每个 seed 先 clip `[-1,1]` 再平均，`delta=10`，`gate=n/(n+5)`，分数 `-original_rank+10*gate*mean_clipped_score`。分数相等保持原热度排名。无历史在所有方法下严格返回 baseline。禁止重新选择 delta、seed、变体或门控。

本测试不使用神经 user encoder 或 ANN 文章向量，因为冻结候选配置本来只有 popular 路由，v3 内容残差直接读取文本特征。不得把本项写成深度编码器跨语言验证。

## 5. 指标、区间与一次性判定

主指标 `HitRate@10 = top10 包含目标的请求数 / 所有固定评估请求数`。每请求恰有一个目标，因而也是本任务定义下的 micro Recall@10。目标未成熟、已读过滤、未知文本或候选不足仍留在主分母。报告每个方法的整数命中、相同总分母、HitRate@10、HitRate@100、MRR@10（未命中为零），及整体和三个固定日的结果。

主效应为 `full13+gate - baseline` 的配对 HitRate@10 差。以匿名用户为簇，先跨三个评估日合并每用户的命中差和请求数，再用 `np.random.default_rng(2026)` 有放回抽取相同数量的用户簇 1,000 次，每次计算总命中差 / 总请求数，报告 percentile 双侧 95% 区间。每日区间也独立重置 seed 2026。其他三项相对 full 的差与区间仅作描述性消融，不作多重选择。

只在整体主差点估计和 95% 区间下界均大于零时，描述为“此预注册样本上的正向外部迁移证据”；否则如实写“本外部测试未支持正向迁移”。无论结果如何不再拟合或选择新方案。用户簇区间仍条件于仅三天的共同反馈流，不能代表未来多日、跨语言总体或生产流量置信度。不得借日内某个正结果取代整体主结论。

诊断固定报告：总事件数/去重数/有效用户文章数、每日可抽样数、实际样本数与 SHA、空历史数、不可见目标数、已读目标数、候选 shortfall、近期不足补位数、100 候选可达率，以及文本/类别覆盖。所有方法每请求候选 ID 集合和 HitRate@100 必须完全相同。

## 6. 执行前后审计
