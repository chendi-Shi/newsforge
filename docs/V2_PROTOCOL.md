# NewsForge v2：延迟反馈、时效候选与上下文重排协议

v2 是看过 v1 官方 dev 结果后开展的后续 benchmark 研究。v1 的正式排序、5,000 请求点击召回与系统结果均保留；该 dev **不能再称为从未触碰的独立测试集**。v2 的窗口、候选方案和模型选择仍仅依据内部 split 1；配置冻结后，dev 按本协议一次性完整报告全部预定对照，不能据 dev 再择优修改配置。本文是执行前的协议初稿，不代表尚未运行的组件、训练或改进已经验证。

## 数据与最低信息预算

保持 v1 的来源、固定特征、原始数组及模型文件不变。统一 UTC 仅是源无时区时间的排序坐标：split 0 为 2019-11-09 00:00:00 至 11-14 07:30:28；split 1 至 11-14 23:59:59；官方 dev 为 11-15 00:00:00 至 23:59:43。

对请求时刻 `t`，取整点 `T=floor(t/3600)*3600`，反馈截止 `C=T−3600`。统计与可用目录都只能使用 **source_timestamp < C** 的信息，不能包含等于 C 的事件，也不能包含同秒或同小时稍后曝光的信息。目录可用规则为 `news_id>0 and first_seen<C`。`first_seen` 来自历史或曝光中最早观察到新闻 ID 的请求时间，只能称首次观察，不能称发布时间。请求自身提供的历史保持与 v1 相同；不从当前标签补入画像，不把当前曝光候选临时加入可用目录。

MIND 没有真实点击到达时间。1 小时反馈延迟是明确声明的回放假设，不证明实际线上点击和未点击反馈能在该时刻确定。正负反馈及曝光分母按同一成熟截止释放；训练过的参数和静态完整训练统计也必须在查询信息边界之前可用。因此内部评估固定从 **1573722000（2019-11-14 09:00:00 坐标）** 开始；此前 split 1 事件可以在延迟成熟后进入滚动状态，但不进入调参指标。模型选择不重训或改写 v1 文件。

开发期的每次回放使用同一确定性事件流。dev 的在线状态可使用过去已成熟的 split 0、split 1 和较早 dev 事件；当前或未来 dev 标签不能影响当前输出，只有请求完成并在以后快照成熟时才能生效。这是预序贯回放，不是将整个 dev 标签拟合成静态特征。事件只处理一次，不能因为同一请求被抽样、重复测量或被多个方案使用而重复累计。原始 train/dev impression ID 可能重复，唯一身份使用全局数组 row。

## 独立时间产物与 EMA 约定

`python -m newsforge.v2.temporal --data data/processed --output data/temporal_v2` 生成新的时间产物，拒绝覆盖已有目录；正式全量构建须等待主任务资源调度。构建仅用 NumPy 与标准库，原数据只读。每个 chunk 最多 200,000 条候选，不创建 97,592,931 行的时间展开数组或全量候选副本。

先将事件累积为每小时、每新闻的曝光/点击 histogram，再串行生成 float32 `[hour, news]` 快照。固定半衰期 12 小时：

```text
decay = 2**(-1/12)
state(C) = decay * state(C−3600) + histogram[C−3600, C)
snapshot(T) = state(C), C = T−3600
```

整小时内的事件统一在该小时结束时计时，所以新纳入小时的 histogram 在 C 处未衰减；这是按小时聚合的近似 EMA，不是假装知道逐事件精确衰减或真实点击到达时间。快照覆盖全部 train/dev 小时，最初两个快照没有已成熟反馈，全部为零；PAD=0 永远为零。全局 prior 为 `sum(clicks,float64)/max(sum(exposures,float64),1)`，完全空状态取零。

`TemporalStore(path='data/temporal_v2', processed_dir='data/processed')` 暴露只读 mmap。`snapshot(t)` 返回 `index/as_of_start/cutoff/clicks/exposures/mode`；时间超出原数据 min/max 时刻即报错，最后小时内晚于最后源时刻也不静默外推。`age_hours(ids,t)` 返回严格可用新闻的 `(T−first_seen)/3600`，PAD/不可用新闻返回零，必须另保留 known mask。frozen 对照使用原 split 0 的静态点击/曝光计数，但采用与滚动方法完全相同的严格目录过滤；在 `C<=train_cutoff` 时拒绝访问 frozen 全训练统计，避免早期训练行读取自身或未来标签。

`manifest.json` 保存 policy、规范 JSON 的 policy hash、源 manifest 与各源数组 SHA256、构建源码 SHA256、各 histogram/快照文件的 SHA256/shape/dtype、时间范围、原始计数核验、chunk 上限和采样 RAM。`TemporalStore.version` 是该 manifest 文件的 SHA256，`policy_hash` 单独绑定计算约定。默认载入验证所有摘要，失败即拒绝使用。RAM 采样包括映射页，可能遗漏采样间的峰值，不将共享桌面观测当精确分配峰值。

## 候选窗口选择与消融

从 split 1 且 `timestamp>=1573722000` 的请求，用 RNG seed 2026 无放回固定抽取 **2,000 行**，原 row 序保持一致。所有候选策略共享相同严格可用目录、已读过滤、请求、标签分母和最终 **100 个唯一候选**预算；不足时报告实际 shortfall，不借用未来或已读文章补齐。时效窗口根据首次观察年龄限制候选，不称新闻发布窗口。

**模型选择也服从反馈成熟约束**：上述候选 2,000 行与最终排序选择的 6,000 行都额外要求 `timestamp<1573772400`（11-14 23:00）。最早 dev 请求是 11-15 00:00，其反馈截止为 11-14 23:00；等于或晚于该截止的内部标签不能用于选择该请求所使用的配置。最初训练入口曾在较宽内部窗口记录验证结果，作为开发记录保留；9 个模型均固定训练 80 轮、关闭提前停止，验证不更新权重。正式流程使用独立的成熟窗口重选入口，对同一批已训练权重重新评分并生成 `ranker_matured_selection.json`，随后只使用这个文件冻结服务和完整 dev 的选择。

双塔同样在这个成熟窗口上重新选择：候选仅限 `mean_random` seeds 17/29/43 的固定完整第 2 轮状态，不重调 epoch。载入时必须核验实际 state 摘要与原训练日志的第 2 轮摘要一致，两个 epoch 均覆盖全部 2,869,013 个训练正例，且三模型训练配置一致。原训练中的验证分数只决定 checkpoint 保留，不反馈优化器；这三份实际保存的状态均为完整第 2 轮，因此可作为固定训练预算候选重选。`backbone_matured_selection.json` 保存三模型完整候选指标与获选权重身份；文章向量和 NumPy 用户编码器必须绑定最终选定 state。

先只在这 2,000 行内部比较 **24/48/72 小时**窗口，以全点击 micro Recall@100 选择。然后在相同样本比较以下完整集合：full、去热度、去 content、去 tower、纯热度、纯 content、纯 tower、无时效、冻结反馈。内部最终选择允许 full、三个去部件、三个单路和无时效方案择优；冻结反馈仅作为信息预算对照，不作为部署方案候选。并列规则、融合与去重补位规则由实现固定写入实验配置，不可看 dev 后更改。

去部件比较必须仍保持 100 候选；若通道融合预取更多结果，应另报总预取数量和 CPU 成本，不能把更多候选预算造成的提升解释成模型贡献。无时效对照仍满足严格首次可观察边界，只取消 24/48/72 小时年龄窗。冻结反馈与滚动方案共享目录、窗口和融合规则，其差值包含新增可用历史反馈的价值，不能归因为单纯计算优化或在相同信息下的算法优势。只有相同滚动信息预算内的去部件对照能帮助判断每个候选通道的增量。

窗口和最终策略冻结后，dev 使用与 v1 相同的 RNG 2026 **5,000 行**，报告全套预定方案。主要分母保持全部日志点击；另报严格目录与已读过滤后的 eligible 点击、首次观察晚于 train cutoff 的 cold eligible 点击、不可用和已读点击数。不允许因窗口变窄而缩小主要分母。保持完整失败结果；窗口/各消融不能分别依据 dev 再选最优。

消融执行时，同一请求、同一窗口与路由预算的语义 top-ID 可以复用；请求历史或时间变化立即失效，反馈热度、融合、过滤与分母仍逐方案计算。启用前用 16 个固定内部请求 × 9 个方案进行 ABBA 顺序的逐字段精确等价验证，保存 `query_cache_equivalence.json`。该优化只改变实验调度；各方案记录的耗时是共享计算下的边际耗时，不能比较独立策略延迟。HTTP 服务默认关闭请求路由复用，服务性能另外实测。

## 重排实验

预定 `content_only/context_only/full` 三种输入方案（15/7/22 维），每种 seeds 17、29、43；按固定 **6,000 行内部验证**选择方案与模型，仍要求同一时间起点与严格快照边界。训练阶段所有时间统计从该训练请求的历史快照获得，不能使用全训练静态计数作为早期训练样本的标签特征。三种方案共享 RNG 2026 抽取的 100,000 个训练正例，每个配 4 个同曝光负例，共 500,000 行；不依据可用内存偷偷缩小预算。固定 HistGradientBoostingClassifier：80 轮树、15 叶、63 个 bins、学习率 0.1、L2=1、关闭提前停止、单线程。三个 random_state 主要影响分箱子采样，不应描述成三种神经网络初始化；即使 seed 结果相同也照实报告。用相同 22 维特征缓存的列切片做消融，模型输出是 1:4 采样条件下的排序分数，不能当总体校准 CTR。

配置固定后，在固定 **12,000 行 dev** 上报告三种方案 × 三 seed；内部选定方案另做全部 **376,471 个 dev 曝光组**的完整候选评估。12,000 行选择规则须在实现配置中固化，不能按标签、模型分数或观察到的结果选样。全量部署方案由内部验证选出，不从 dev 九组中挑最高分。重排相同 100 候选不会改变 Recall@100，候选增益与 top-10 顺序变化分别报告。

## 诊断、验证与结论限制

轻量 mmap 诊断表明数据时间分布变化明显：v1 固定 dev 样本的 7,560 个 eligible 点击中 5,686 个为 train-cutoff 后首次观察新闻，6,293 个没有训练点击计数；对应内部 5,000 行诊断仅 467/7,559 个 train-unseen。该诊断用于明确 v2 的开发背景，不作为未见 dev 证据。目录 first_seen 年龄、历史条目的首次观察年龄都不能当真实发布时间或用户点击年龄。

合成测试必须验证：修改未来标签不能改变更早快照；cutoff 等号和同秒事件严格排除；PAD 与空初始状态正确；源/快照同大小损坏被 SHA256 拒绝；时间越界和过早访问 frozen 统计报错。全量构建后核验所有 histogram 曝光/点击合计与源 manifest 一致。

统计报告区分训练 seed 波动与用户聚类的评估不确定性；配对比较使用相同请求、相同主要分母。固定 dev benchmark 曾参与 v2 研究动机，且回放延迟是假设、未曝光新闻无完整相关性标签，没有 propensity 不能称 IPS 反事实评估。CPU 实测、离线提升或运行成功均不等于线上 A/B、SOTA、分布式加速或生产可用性。
