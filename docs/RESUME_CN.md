# NewsForge：大规模新闻推荐研究与 CPU 服务优化

个人研究项目｜Python / PyTorch / NumPy / scikit-learn / FastAPI｜[GitHub](https://github.com/chendi-Shi/newsforge)

- 构建 MIND-large 推荐管线，流式处理 **260.9 万曝光组、9759.3 万候选记录**，使用分块扫描与 memmap 完成数据审计、时间切分和内容特征处理，在 **1 小时反馈成熟假设**下建立 **168 个小时快照**。
- 实现 PyTorch 双塔、候选相关注意力与同曝光难负例训练，完成 **3 配置 × 3 seeds、各 2 个完整 epoch**；区分曝光内排序与目录召回，以固定候选预算进行消融并保留负结果。
- 针对 HGB 重排降低 Top10 点击覆盖的问题，设计基于 13 维内容交互特征的**热度排名约束线性成对偏好残差**，完成三 seed、三特征变体及时间分隔的拟合/选择/确认；在固定 5,000 请求、100 候选下，Recall@10 从 **23.482% 提升至 23.904%**，差值 **+0.422 个百分点，用户簇 95% CI [0.107, 0.762]**，Recall@100 逐请求不变。
- 优化热度路径的小时缓存与已读过滤，移除无用双塔计算；同请求 ABBA 实验实现**热缓存检索 2.59 倍加速**，1,536 个候选批次逐字段完全等价。冷派生缓存无加速，未将微基准倍数表述为端到端收益。
- 接入 FastAPI 单条/批量服务，发布模型和独立环境重新训练的模型分别完成 **768 次 HTTP 查询、13 项契约检查**，全部响应字段与离线结果完全一致；另对 64 条质量评估请求核验实际服务 Top10 顺序，建立含 **134 个文件摘要**的研究证据审计链。
- 建立 **36 个运行依赖与 45 个完整研究依赖的 wheel 哈希锁、制品迁移与复训验收流程**；扩展后的 GitHub 独立 Windows 环境 **366 项测试全部通过、无跳过**，本机从冻结处理数据和 v2 基线重训的 **9 个 v3 线性残差模型字节完全一致、62 项对照检查通过**，覆盖逐请求消融计数、置信区间、选参和服务决策。
- 对 Adressa **308.3 万条去重访问**开展冻结模型迁移测试，固定 **15,000 请求**并报告全部消融、配对用户簇区间及词表覆盖；发现主指标下降 **0.373 个百分点**，保留负迁移结论，以 **128 请求独立慢速审计和全部请求的保存数组核验**验证实现一致性，明确类别输入退化及跨语言应用边界。

可替换的曝光内排序条目（与目录 Recall 是不同任务）：相同 50 万训练行、三 seed 下，HGB 从 15 维内容特征扩展至 22 维内容与时序特征，在 12,000 曝光组上的平均 nDCG@10 从 **0.36996 提升到 0.41501**，差值 **+4.50 个百分点，95% CI [4.01, 4.93]**；内部选定单模型在完整 37.6 万曝光组上达到 **0.42005**。[v2 证据](../reports/V2_RESULTS.md)

口径与面试准备：本项目使用公开 MIND 数据，未使用腾讯内部数据。dev 是已观察 benchmark；+0.422 pp 不等于 +0.422% 线上 CTR。服务使用确认前冻结的 `full13 + gate, δ=10`；MIND 消融没有证明显式类别列、最后历史交互列或门控各自有稳定正收益，不能声称所有组件都有效。2026-10-14 两次复验的单条串行 HTTP p95 为 **87.58 / 166.89 ms**、吞吐 **25.99 / 16.46 query/s**，均为共享桌面观测，不是生产 SLO；不能拿它们与历史时延计算算法加速比。该轮本机联合验收 249 项通过、2 项因符号链接权限跳过，对应 CI 的 251 项全部通过；后续扩展 CI 的 366 项也全部通过。上述字节一致复训继承原有处理数据和 v2 基线，没有从原始数据重训全部系统。Adressa 为独立出版商的历史访问压力测试，使用原发布模型；资源行数上限在部分事件已读取、效果未产生时单独修订，不能称完全事前的资源注册。外部结果不支持正向迁移，也不是未来泛化、线上 A/B 或多机分布式验证。
