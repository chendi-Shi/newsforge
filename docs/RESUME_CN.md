# NewsForge：大规模新闻推荐研究与 CPU 服务优化

个人研究项目｜Python / PyTorch / NumPy / scikit-learn / FastAPI｜[GitHub](https://github.com/chendi-Shi/newsforge)

- 构建 MIND-large 推荐管线，流式处理 **260.9 万曝光组、9759.3 万候选记录**，使用分块扫描与 memmap 完成数据审计、时间切分和内容特征处理，建立严格延迟反馈的 **168 个小时快照**。
- 实现 PyTorch 双塔、候选相关注意力与同曝光难负例训练，完成 **3 配置 × 3 seeds、各 2 个完整 epoch**；区分曝光内排序与目录召回，以固定候选预算进行消融并保留负结果。
- 针对普通重排损害目录覆盖的问题，设计**热度排名约束的成对偏好残差**，完成三 seed、三特征变体及时间分隔的拟合/选择/确认；在固定 5,000 请求、100 候选下，Recall@10 从 **23.482% 提升至 23.904%**，差值 **+0.422 个百分点，用户簇 95% CI [0.107, 0.762]**，Recall@100 逐请求不变。
- 优化热度路径的小时缓存与已读过滤，移除无用双塔计算；同请求 ABBA 实验实现**热缓存检索 2.59 倍加速**，1,536 个候选批次逐字段完全等价。冷派生缓存无加速，未将微基准倍数表述为端到端收益。
- 接入 FastAPI 单条/批量服务，**193 项测试、13 项 HTTP 契约检查通过**；768 次 HTTP 查询所有响应字段与离线服务完全一致，另对 64 条质量评估请求核验实际服务 Top10 顺序，建立含 **134 个文件摘要**的证据审计链。

可替换的曝光内排序条目（与目录 Recall 是不同任务）：相同 50 万训练行、三 seed 下，内容与上下文合并使 12,000 曝光组的平均 nDCG@10 从 **0.36996 提升到 0.41501**，差值 **+4.50 个百分点，95% CI [4.01, 4.93]**；内部选定单模型在完整 37.6 万曝光组上达到 **0.42005**。[v2 证据](../reports/V2_RESULTS.md)

口径与面试准备：本项目使用公开 MIND 数据，未使用腾讯内部数据。dev 是已观察 benchmark；+0.422 pp 不等于 +0.422% 线上 CTR。新服务使用确认前冻结的 `full13 + gate, δ=10`；消融没有证明显式类别列、最后历史交互列或门控各自有稳定正收益，不能声称所有组件都有效。单条串行 HTTP 本机 p95 **63.20 ms**、**31.63 query/s**，健康服务窗口峰值 RSS **226.43 MiB**，均为共享桌面实测，不是生产 SLO 或分布式加速。
