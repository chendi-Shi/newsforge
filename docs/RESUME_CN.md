# NewsForge：严格延迟反馈下的新闻推荐研究与 CPU 服务

个人研究项目｜Python / PyTorch / NumPy / scikit-learn / FastAPI｜[GitHub](https://github.com/chendi-Shi/newsforge)

- 构建 MIND-large 推荐管线，流式处理 **260.9 万曝光组、9759.3 万候选记录**，以分块扫描和 memmap 完成数据审计、时间切分及仅训练期拟合的文本特征处理。
- 实现 PyTorch 双塔、候选相关注意力与同曝光难负例训练，完成 **3 配置 × 3 seed、各 2 个完整 epoch**；构建固定 100 候选池的多路召回消融，区分日志内排序与目录点击覆盖并保留负结果。
- 在相同 **50 万训练行、三 seed** 下完成内容与时间上下文特征消融：12,000 曝光组的 nDCG@10 从 **0.36996 提升至 0.41501**，差值 **+4.50 个百分点，95% CI [4.01, 4.93]**；内部选定单模型在完整 **37.6 万曝光组**上达到 **0.42005**。
- 实现严格延迟的 **168 个小时快照**、成熟内部选择与 NumPy/FastAPI 服务；**148 项测试、13 项 HTTP 契约检查通过**，四种批量/并发配置的 **768 次查询与离线结果完全一致**。

口径：排序提升是内容特征与合并特征在同一 12,000 曝光组上的三 seed 平均值之差，区间按用户聚类；全量值属于内部选定单模型。目录服务最终采用 `popular_only / 24h / 无重排`，Recall@100 为 44.47%（5,000 请求），HGB 未部署为该服务的重排器。本机单请求串行 p95 为 203.83 ms、15.72 query/s，不能写成性能加速或生产 SLO。v2 已观察过 v1 dev，滚动反馈与冻结统计的信息预算不同，不声称线上 CTR 或分布式加速。
