# 如何讲清 NewsForge 的研究贡献

**问题从哪里来？** v1 的 ANN 近邻准确率和日志点击召回是两件事。ANN 可以准确找到某个向量空间的近邻，但如果用户画像过时、文章库大部分已失去时效，近邻未必是用户下一次会点击的新闻。v1 的低点击覆盖推动了 v2 的数据时间分布诊断。

**为什么不直接上更大的模型？** 当前项目在无 GPU 的电脑完成。先用真实曝光和首次观察时间检查失效原因，再比较时效候选、衰减统计、已有双塔和内容通道。这样能区分数据与候选问题、排序问题、近似检索问题，不把全部失败都归因于模型容量。

**怎样防止时间泄漏？** 对时间 t 的请求，快照整点 T 向下取整，截止 C=T−1 小时。只有时间严格小于 C 的事件能进入统计；当前请求及等于 C 的事件均不包括。目录也按 first_seen<C 过滤。训练样本读取各自过去的状态，而不是把全训练期点击计数回填到早期样本。

**选择模型本身会不会泄漏？** 会，不能只检查在线特征。最早 dev 请求在 11-15 00:00，允许的反馈截止为 11-14 23:00，所以最后一小时的内部验证标签也不能用来选择这时部署的模型。代码将最终验证限制为 09:00≤t<23:00，同时覆盖排序、双塔和候选方案选择；旧宽窗口指标作为开发记录保留。重选前验证 HGB 固定 80 轮且关闭早停，双塔实际状态等于固定第 2 轮，避免把依赖旧验证的早停权重当成独立固定候选。

**用早些时候的 dev 点击是否作弊？** 本项目明确采用预序贯回放：假定反馈在至少一小时后成熟，逐时更新状态，不能把未来反馈带入当前预测。这比 v1 的冻结训练统计有更多可用信息，二者不是同信息预算的算法比较。冻结对照还同时去掉了 EMA 时间加权，不能将全部差值称为单纯新增反馈收益。v2 又是在看过 v1 dev 后提出的，所以必须称后续 benchmark 研究，不能称全新的未见测试。

**每个模块怎样归因？** 候选方案共享查询、截止规则和 100 个最终候选，分别去掉热度、内容、双塔或时效窗；保留单通道与冻结统计对照。排序方案共享同一 50 万训练行、树容量和验证候选，比较内容、上下文、两者结合。用户簇配对 bootstrap 用于同一请求上的差值；三个训练 random_state 的波动另外报告。

**怎样避免为了展示而挑结果？** 窗口、候选组合和服务是否重排都只用内部验证选择。选择文件绑定数据、源码、模型和特征摘要，dev 阶段拒绝不匹配的文件。全部预定对照都会报告，失败的通道不会因为已实现就强行保留。逐项结论以 [实测消融报告](../reports/V2_RESULTS.md) 为准。

**排序提升为什么不一定提升 Recall@100？** 重排只改变同一候选集合的顺序，不能找回没被召回的点击。因此看它对 Recall@10 的贡献；Recall@100 应保持相等。完整曝光组的 nDCG 则是另外的排序任务，不能与全目录点击召回混用。

**这轮实际保留了哪些结论？** 三 seed 的合并排序特征在 12,000 个 dev 曝光组上 nDCG@10 为 0.41501，相比内容和时间上下文分别增加 4.50、3.97 个百分点，两组用户聚类 95% 区间均为正。但将合并 HGB 用于选定目录候选的重排，Recall@10 下降 10.10 个百分点；完整融合的内容和双塔通道也有负向增量。因此服务沿用内部验证选定的 24 小时热度候选，并关闭重排。日志曝光与检索候选的分布差异是可能解释，尚未被单独归因验证，不能写成已经证明的原因。

**下一轮如何改进？** 需要独立的后续时间段，先验证候选分布与训练曝光分布的差异，再在固定检索预算下比较经过内部选择的融合权重和适配候选分布的排序训练。目录中没有曝光的文章缺少点击标签，不能直接当成真实负例。上述是后续研究方向，本仓库不把它们列为已完成成果，也不继续用当前 dev 调参。

**工程上做了什么？** 用流式分块和只读 memmap 处理约一亿候选曝光，快照与模型做摘要绑定；同一个特征实现用于训练、评估和服务；NumPy 用户编码与 PyTorch 核对；统一并列分数规则；API 过滤全部传入历史，最后 20 条用于模型画像，MIND 离线回放的输入本身只保留最近 20 条，不能宣称排除了完整原始点击史；实际 HTTP 与离线输出逐项对齐；验证 Windows 启动器子进程的归属并清理自己创建的服务。

**哪些事情还没有证明？** 没有线上 A/B、真实点击到达日志、曝光 propensity 或独立新增时间段；没有腾讯内部数据、GPU、分布式训练实测或 SOTA 结论。新模型是内容特征与因果历史统计的 CPU GBDT，已有双塔是本项目训练的 PyTorch 模型；不要把它包装成原创大型新闻语言模型。
