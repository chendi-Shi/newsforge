# NewsForge v3：固定候选预算下的有界个性化重排

本文在 v3 正式拟合、选择和评估前规定问题、时间边界、方法、消融及部署判据。协议描述待验证的方案，不预设个性化一定有效，也不代表实验已经完成。

v3 已知 v1/v2 的官方 dev 结果，研究动机包括 v2 中目录个性化融合与直接重排未能胜过热度。因此，官方 dev 是**已观察过的后续研究 benchmark，不是新的、从未触碰的独立测试集**。新的时间切分能约束本轮拟合与参数选择，却不能消除先前研究对方法设计的影响。继承的 24 小时首次观察窗口、文本表示和热度规则也不是在本轮确认集之外首次确定的设计；报告必须保留这个限制。

## 1. 要回答的问题与固定信息预算

问题限定为：在 v2 热度方案生成的同一组最多 100 个候选上，使用轻量内容配对模型、小幅排名扰动和历史长度门控，能否改善前 10 位的日志点击覆盖，同时控制对强热度基线的破坏？

所有方法共享下列约束：

- 源数据、特征和新闻索引继承 v2，只读使用；不重写 v1/v2 证据。
- 请求时刻为 `t`，小时起点为 `T=floor(t/3600)*3600`，反馈截止为 `C=T-3600`。反馈仅可来自 `source_timestamp<C`；等于 C 的事件也排除。
- 可用新闻满足 `news_id>0 and first_seen<C`；24 小时窗口延续 v2 的首次观察年龄规则。`first_seen` 是可观察代理，不是真实发布时间。
- 保留 v2 的完整已读过滤、窗口不足时的补位及并列规则。候选来自相同的滞后 EMA 热度，最终预算均为最多 100 个唯一 ID，不加入当前曝光候选或标签来补齐目录。
- v3 只改变顺序，不能改变候选集合、候选来源或 shortfall。所有方法对每个请求的 Recall@100 命中数必须完全相同；差异应导致审计失败，不能解释为模型提升。
- 用户画像仅来自请求提供的最近最多 20 条历史。不得用当前点击、未来曝光或整个验证期汇总的用户标签补建画像。请求自带历史与延迟公共反馈是两种已声明的信息来源。

1 小时反馈延迟是 MIND 缺少真实点击到达时间情况下的回放假设。较早请求的反馈成熟后可进入后续快照；同一源事件只累计一次，不能因多方法、多轮评估或重复 HTTP 请求再累计。

## 3. 仅在 fit 上构建曝光内配对

对每个固定 fit 请求，从其实际曝光候选中读取正例 `label=1` 和非点击项 `label=0`。每个正例使用当前 seed 的 RNG 在**同一曝光组**的非点击项中放回抽取 4 个负例。seeds 固定为 17、29、43；每个 seed 的配对样本必须保存摘要，三个特征消融使用同一 seed 的完全相同配对。

没有正例或没有非点击项的组不产生训练对，记录其数量与原因。任何与该组正例 ID 冲突的项都不能成为该组负例。重复抽中同一项可以出现，必须计入实际样本数，不能声称每对均来自不同物品。

这里的负例是日志中的已曝光非点击项。**不把未曝光目录新闻伪造为负例**；同时，非点击也不证明用户不感兴趣，因此不能宣称已消除所有假负例或获得完整相关性标签。训练是离线监督排序，不是 IPS、反事实推荐或线上奖励优化。

训练目标对每个配对等权。含多个点击的曝光组产生更多训练对；重复抽样的物品也会获得更高权重。因此本轮目标不是曝光组等权目标，必须披露这一点。

## 4. 三种特征与配对模型

沿用 v2 NumPy 内容特征定义的前 13 列，禁止临时修改列语义。它们不含热度或全局标签统计：

| 列索引 | 特征 |
|---:|---|
| 0–3 | 历史与候选完整特征余弦相似度的 mean、max、top3 mean、std |
| 4–6 | 文本余弦相似度的 mean、max、top3 mean |
| 7–9 | 平均历史文本画像与候选的 cosine、平均绝对差、L2 距离 |
| 10–11 | 类别重叠的 mean、max |
| 12 | 最后一条有效历史与候选的文本余弦相似度 |

预定特征消融为：

- `full`：全部 13 列。
- `no_category`：删除第 10、11 列的显式类别重叠，剩余 11 列。
- `no_recent`：删除第 12 列的最后一条有效历史专用交互，剩余 12 列。

这是列组增量消融，不是信息完全擦除：第 0–3 列的完整特征余弦仍包含类别 one-hot，因此 `no_category` 不能称为完全没有类别信息；最后一条历史仍参与其他历史聚合，因此 `no_recent` 也不是删除最近一次行为。报告应使用“显式类别重叠列”和“最后历史专用交互列”的准确描述。

每个 seed 的标准化均值和标准差只从该 seed 所有训练对的正、负特征联合矩阵计算，按配对中实际出现的次数重复计权；标准差使用 `ddof=0`。零方差列的 scale 置为 1。同一 seed 的三个变体共享保留列的相同标准化统计，不能分别改采样。tune、confirm、dev 或它们的候选特征均不能参与标准化。

记标准化后的正负差为 `d_p=(x_p^+−x_p^-)/scale`，无截距线性模型的固定目标为：

```text
L(w) = mean_p logaddexp(0, -w·d_p) + (0.01/2) * ||w||²
```

优化器固定 `L-BFGS-B`，`maxiter=200`，不做早停或依据后续指标增加迭代数；拟合代码必须保存其实际停止条件、优化器状态、迭代次数、目标值与梯度信息。数值异常或未满足实现规定的成功条件不能静默宣称训练成功，应先中止后续阶段并记录失败。三 seeds × 三变体共 9 份模型；seed 差异主要来自负例抽样，不称为三种神经网络初始化。

无截距使同一用户曝光组的正负差目标明确；原始线性分数及下面的截断残差都不是校准 CTR，也不能当作点击概率。

## 5. 有界残差、门控与严格回退

设固定热度候选的原始排名为 `r_i=0,1,...,m−1`，m≤100。对某一特征变体的三个 seed：

```text
raw_j(u,i) = ((x(u,i) − mean_j) / scale_j) · w_j
z(u,i)     = mean_j clip(raw_j(u,i), -1, 1)
n(u)       = 请求有效历史条数，使用与内容特征一致的最多20条历史
g(u)       = n(u) / (n(u) + 5)
s(u,i)     = -r_i + δ * g(u) * z(u,i)
```

先对每个 seed 分数截断，再求均值；不能替换为先平均再截断、sigmoid、候选内重新标准化或排名分位数。均值、scale 和模型权重只取对应 fit 产物。

按 `s` 降序排序，分数并列时原热度排名较小者优先。`δ=0` 必须严格返回原候选顺序。空历史必须严格回退热度，即使 `no_gate` 对照也不能引入模型截距式偏移。`no_gate` 使用与 `full` 完全相同的三份权重，仅将非空历史的 g 设为 1；不另拟合模型。

由于 `|g*z|≤1`，若两个物品原排名距离严格大于 `2δ`，它们不能发生顺序逆转；原排名距离等于边界时并列仍保留原顺序。这不是“每个物品最多移动 δ 位”的承诺，也不能据此宣称 top10 效果必然不下降。

## 6. 调参、确认与部署判据

预先指定的主方案是 `full + gate`。唯一可由 tune 选择的超参为 `δ∈{0,2,5,10}`。选择 tune 全部日志点击分母下 micro Recall@10 最大者，完全并列时选较小 δ。不得根据 tune 改门控常数、特征、L2、优化器、负例数、seed、候选窗口或融合公式。选择完成后，保存全部候选 δ 的结果和最终选择，冻结模型、参数、来源摘要。

confirm 只比较冻结的 `full + gate` 与热度基线。部署门槛在执行前固定为同时满足：

1. 配对 micro Recall@10 点增益严格大于 0；
2. 该增益的配对用户簇 bootstrap 双侧 95% 区间下界严格大于 0。

未达门槛，包括 δ=0、零点增益或区间跨 0，均继续使用原热度服务。不能据 confirm 换成另一个 δ、另一个特征消融或 no_gate。此阶段因此是预声明部署决策集，不是完全不影响部署的独立最终测试。

dev 无论部署门槛是否通过，都按同一冻结 δ 报告：热度、`full + gate`、`no_category + gate`、`no_recent + gate`、`full + no_gate`。消融不各自重新选 δ，部署也不根据 dev 切换。区分“候选研究方案的 benchmark 指标”与“实际保留的服务配置”。

## 7. 指标、区间与解释范围

目录主指标是 micro Recall@10：所有评估请求 top10 命中的日志点击数之和，除以这些请求全部日志点击数之和。分母不因24小时窗、历史过滤或候选生成失败缩小；同时报告请求数、全部点击数、可用点击数、重复已读点击数和 shortfall。所有消融与基线使用相同请求、分母、用户及候选集合。

Recall@100 为候选不变量和诊断指标，不作为重排收益。除主指标外可以报告前10排名相关指标，但不能依据这些次要指标重新选择 δ 或宣称在线 CTR 提升。若另做完整曝光候选 nDCG，那是不同任务，必须单列结果，不能代替目录召回证据。

区间使用配对用户簇 bootstrap，固定 1,000 次、RNG seed 2026。先将每个用户的命中差及全部点击分母加总，再有放回抽取用户簇；每次计算被抽用户的总命中差除以总点击数。不能把逐请求 Recall 的均值当成 micro Recall，也不能把同一用户的请求拆成独立样本。报告 percentile 2.5% 和 97.5% 分位点及有效重复数。

确认门槛只针对一个预定方案相对一个基线。dev 的多个消融区间不经过多重比较校正，属于探索性解释，不能看到某个区间显著后选择性声称整体确认成功。各 seed 的效果若另行列出，应与用户重采样区间分别解释；模型集成不是三个独立测试集。

用户簇区间条件于同一天已实现的反馈流、固定候选和已有表示，不反映所有时间相关性、模型开发选择或跨日期不确定性。不能由单日正区间推断跨域泛化、线上 A/B 收益或生产稳健性。

## 8. 产物、摘要与执行审计

v3 使用独立产物及报告目录，不覆盖 v1/v2 文件。正式阶段开始前冻结本协议、计算源码和配置；后续发现实现错误时，保留失败产物、说明修复原因，使用新证据目录重新执行受影响链条，不能在同名正式结果中静默替换。

每阶段至少绑定并验证：

- 本协议、全部计算和指标源码、依赖版本、精确公式、超参网格、优化器设置、随机数策略。
- 源 manifest，特征、历史、候选、标签、offset、时间、split、用户、首次观察和新闻 ID/类别映射等所有实际输入文件的 SHA256。
- v2 热度及窗口配置、时间产物 manifest/policy、所读快照数组的 SHA256；若引用现有 source manifest 作间接绑定，加载时必须验证其实际文件摘要，不能只相信 JSON 声明。
- 三个内部阶段和 dev 的 row 数组、时间 min/max、split 分布、row SHA256；拟合对的源 row/正负 ID、采样 seed、配对数与摘要。
- 每份模型列索引、mean/scale、权重、训练配置、优化器结果、模型文件摘要；同 seed 消融的配对及标准化一致性证据。
- 每请求 canonical 候选 ID、offset、原排名、特征与分数缓存及其摘要。缓存必须同时绑定模型、公式、数据版本及候选顺序，不能将曝光候选分数错用于目录 top100。
- tune 的全部 δ 结果、唯一选中 δ、选择并列规则、confirm 部署门槛和决策、实际服务加载配置。
- 各方法逐请求命中数、固定标签分母、用户簇信息及报告摘要；原始大数组置于忽略的产物目录，仅发布可核查聚合及复现代码。

最低验证包括：未来标签扰动不能影响较早快照和输出；截止等号不纳入；训练/调参/确认边界及源 row 无交叉；没有未曝光负例；同 seed 消融配对相同；标准化不读取后续阶段；空历史与 δ=0 严格回退；固定候选集合和逐请求 Recall@100 恒等；排序并列规则与有界反转性质；模型/缓存同大小损坏也会因 SHA 不匹配被拒绝；离线与 HTTP 的最终 ID、顺序和分数一致。

如 v3 同时优化热度检索计算，应先独立证明它与 v2 canonical 热度候选在相同请求上逐字段等价，再将其用于质量实验。CPU/内存/HTTP 性能以相同候选及加载配置单独实测，记录批量、并发、warmup、轮次和进程范围。共享桌面计时不等于生产容量，有界重排的质量收益也不等于系统加速。

## 9. 报告纪律

完整发布 9 个拟合结果、全部调参 δ、确认门槛及结论、预定 dev 消融和候选不变量验证。保留负收益、零提升、未通过部署门槛、数值失败及执行中断。若最终保留热度服务，应明确写出，而不是把研究模型的指标包装成上线模型结果。

本轮可能的贡献是可复现的、受信息与候选预算约束的推荐研究与实现；不把结果表述为独立新测试集证明、校准点击概率、因果收益、SOTA、线上 A/B 或分布式加速。
